# Deprecated items still in use

Almost every `#[deprecated]` item left in the SDK takes a device or driver owner that its caller has to hold: a `Gpu`, a `Cd`, a `ControllerPort`, a `Spu` or `Mdec` driver, an `OtFrame`. Replacing one is not a rename. The caller has to take `psx_rt::Peripherals` at boot and pass the token down to where the call is made, which is a change to the game's structure and, in the hot paths, to its code generation. The exceptions are `attributed_clip::clip_convex_plane` and `clip_convex_plane_uninit` (the checked replacement drops the partial count and moves the code, so the two callers need a perf run) and `ot::TAG_SCOPED_TEXTURE_WINDOW` (no effect; removing its three uses changes the staged tags in quake-psx's affine writer, so it needs a frame check). They stay until the callers have moved.

All the pure renames and moves are gone (the removal list is in `CHANGELOG.md`), together with the items nobody called. [MIGRATION-ownership.md](MIGRATION-ownership.md) and [MIGRATION-psx-gpu.md](MIGRATION-psx-gpu.md) say how each remaining item is replaced.

Callers come from compiling each repo's `main` at its own SDK pin with the deprecation lint on (not from searching names), 2026-10-25: nitroxide 92146fb, voxide 44dc725, hk-psx 2cf424d, hl-psx e03e9bc (with its `#![allow(deprecated)]` removed for the scan), cs-psx 4613a46, quake-psx a015b723, oot-psx 813b092, wipeout-psx 35a5479, psxcel 632520c, celeste-collection-psx f5d6416, psoxide-arcade f091fbb, PSoXide-editor 54733099 (the examples, including hardware-tests with its allowance removed). gh-psx, ds-psx, alttp-psx and psx-demo-disc pin an SDK that predates the replacements, so they were not scanned: each of them needs the whole table at its next repin. The editor's frozen oracle fixtures under `engine/crates/psx-goldsrc/tests/oracles/` are compared as text and never compiled, so they do not count.
